# 中文命名与冗余文件整理

本参考用于用户要求中文目录/说明文件名，或将已有项目根目录的多余文件分类。首次资料归档仍默认复制；不要仅因用户使用中文就自动改名，也不要把“多余”解释为允许删除。

## 1. 中文命名范围

以下是对应示例，优先沿用用户或团队已有名称；保留编号顺序。

| 默认名称 | 中文名称示例 |
|---|---|
| `01_Docs/` | `01_项目文档/` |
| `02_Hardware/` | `02_硬件资料/` |
| `03_Firmware/` | `03_固件工程/` |
| `04_Tools/` | `04_开发工具/` |
| `05_Release/` | `05_版本发布/` |
| `README.md` | `项目说明.md`（无需平台自动识别时） |
| `CONTRIBUTING.md` | `开发规范.md`（无需平台自动识别时） |

资料子目录可用“需求文档、设计文档、器件手册、测试文档、使用手册、生产资料、原理图、结构尺寸、物料清单”等名称。自建说明与清单可用“项目结构说明.md、资料归档映射.md、资料校验清单.csv、归档排除清单.csv”。CSV 中被脚本读取的字段名不随文件名一起翻译。

- 保留源码标识、器件型号、版本号和工程标识；`app/`、`middleware/`、`drivers/`、`bsp/`、`config/`、`scripts/`、`test/` 默认保持英文，避免扩大改名范围。
- 保留工具固定名称：`SKILL.md`、`CMakeLists.txt`、`sdkconfig*`、分区表引用、`.gitignore`、`.editorconfig`、`.clang-format`、`.gitlab-ci.yml`、`.github/`、`.gitlab/` 等。平台自动发现所需的 README、贡献指南或模板名称也应保留，必要时另设中文入口。
- 厂商资料的原文件名、第三方许可证以及示例的内部相对目录保持不变。可重命名项目自行创建的外层归档目录。
- 中文父目录可能受工具链限制。构建路径改名后运行可用的受影响检查；没有相应 SDK 时明确说明未验证交叉编译，不以主机测试代替板级验证。

## 2. 根目录冗余文件分类

先检查根目录、实际用途和引用，区分正在使用的配置与备份材料。以下目的地按当前英文/中文结构选择对应名称，不要求新增顶层目录。

| 内容 | 中文结构中的建议位置 | 处理 |
|---|---|---|
| 已复制归档、仍留在根目录的厂商原始资料包 | `01_项目文档/归档备份/原始资料/<原目录名>/` | 用户明确要求整理这类冗余文件时，整体迁移并保留原始内容 |
| 项目结构技能源码、辅助脚本仓库 | `04_开发工具/项目结构工具/<原仓库名>/` | 保留仓库内部结构及 Git 元数据；与已安装技能入口区分 |
| 标准项目 ZIP、历史结构 ZIP | `05_版本发布/项目备份/<快照类别或日期>/` | 按已知快照用途分类，不能仅凭“标准项目”文件名认定为最新产品版本 |
| 本地格式化工具、Python 包缓存 | `04_开发工具/开发环境/` 下的现有缓存目录 | 已在合理位置则保留；移动前核对脚本和 PATH 引用 |
| 构建与测试输出 | 固件工程已有 `build/` 或 `output/` | 保持构建约定并由 Git 忽略，不把输出当正式发布 |
| `.agents/`、根仓库 `.git/`、CI 目录、项目入口 | 原位置 | 确认用途后保留，不因隐藏或技术文件名而归为多余 |

文件夹归类操作只涉及用户要求整理的冗余项。首次迁移、唯一源码或用途不清的材料仍保留原位或列为待确认；已经明确授权的归类不重复请求同一项确认。不删除、不覆盖同名目标，不拆分厂商示例依赖。

## 3. 路径与完整性

1. 列出“原路径 → 新路径 → 分类依据”，确认目标不存在。Windows 的目录迁移前解析绝对路径，验证源和目标均位于用户指定工作区；遇到重解析点先确认实际位置。不要把路径交给另一种 Shell 拼接后执行。
2. 使用可处理长路径的文件接口。Windows 深层资源可采用 `\\?\` 扩展路径；不要把受路径长度限制的 `exists()` / `is_file()` 返回假误当成文件不存在。用独立枚举或来源清单检查覆盖率，不能只相信第一次遍历。
3. 整体移动已授权的目录；对移动的原始资料、工具仓库和 ZIP 比较文件数量、大小及 SHA-256。单纯路径变化不应改变厂商内容和校验值。
4. 同步所有活动引用：Markdown 链接、CMake、CI、Shell/PowerShell/Python 中的路径、发布脚本、`.gitignore`，以及资料清单的 `source` / `destination`。清单原始路径更新时保留迁移记录，不能改写文件内容的 SHA-256。
5. 仅改说明文档或移动备份时检查链接、清单及完整性；涉及固件目录或构建脚本路径时，运行受影响的脚本语法、主机测试、静态/格式检查。实际 SDK 不可用的部分明确列出。
6. 记录当前目录位置、移动统计、校验结果和保留在根目录的必要项。更新项目入口；重复执行时先核对已归类状态，不再重复嵌套备份目录。

## 4. 压缩包与仓库边界

- 项目快照与正式固件版本分开。仅移动已有 ZIP 时保持原包内容，说明其快照时间/阶段；不宣称其自动包含后续变更。
- 用户要求更新交付包时，从最新工作区重新打包，排除原始重复资料、工具缓存、构建输出、项目备份目录以及 ZIP 自身，避免递归包含旧包。保留厂商示例的资源、许可证和相对目录，并校验 ZIP 的 CRC 与归档资料 SHA-256。
- 在 `.gitignore` 中忽略本地原始资料备份、辅助仓库、工具缓存和项目快照；正式发布制品仍按既有版本规则处理。
- 技能仓库发布时仅包含技能入口、参考、脚本及仓库说明，不带入用户的硬件资料、原厂固件、项目快照、凭据或本机绝对路径。

这些规则由代理按任务执行；Python 骨架生成器没有新增中文改名或自动清理命令。
