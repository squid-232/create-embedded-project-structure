# Notion 规范页面模板


在 Notion 中生成项目结构规范页面时，按下面的章节顺序编写。内容按用户的项目定制，不要照抄通用内容。
## 页面结构
1. **开头的 callout**：项目名、类型（MCU+RTOS / Linux）、芯片或 SoC、规范版本、生效日期；附带骨架 zip 时注明骨架版本（如 `gen_embedded_skeleton.py v2.0`）。
2. **项目结构**：顶层目录树代码块 + 每个目录用途的表格。
3. **工程结构**：`03_Firmware/` 目录树代码块，标出本项目的定制目录。
4. **分层与依赖规则**：调用方向图（代码块）+ 每层“职责 / 禁止”表格。
5. **命名规范**：表格（文件、函数、宏、全局变量、静态变量、类型）。
6. **版本与发布**：版本号规则、Git 分支模型、提交信息格式、构建变体（debug / release / factory）、发布步骤待办清单（改 `version.h` → 更新 CHANGELOG → `build.sh release` + `pack.sh release` 归档到 `05_Release/vX.Y.Z/` → 发布测试 → 合并到 main 并打 tag）。
7. **研发流程与交付物**（用户要求研发流程，或同时输出研发工作流规范时加入）：项目阶段 → 交付物 → 存放位置表格、硬件阶段与固件就绪、日常开发闭环、CI 流水线。内容取自“研发工作流参考”子页面，按项目裁剪。
8. **新建模块检查清单**：待办列表（放对层级、.c/.h 成对、static 内部函数、无反向依赖、补单元测试、`check.sh` 和 `run_tests.sh` 通过、更新 README）。
9. **现有资料归档**（做了资料归档时加入）：映射表（原路径 → 目标路径 → 依据 → 备注）、待确认、不入库清单。
10. **附件**：如有，附上项目骨架 zip。
## 格式要求
- 目录树一律用代码块，表格用 Markdown 管道表格。
- 不要用 H1 重复页面标题；页面图标用 📁 或 🗂️。
- 中文用户用中文编写，目录名、代码标识符保持英文。
- 文件名、路径、命令一律用行内代码（如 `McuRtosTemplate.zip`、`scripts/check.sh`），否则 Notion 会把 `xxx.zip`、`xxx.sh` 这类文字自动识别成网址。
- 使用当前 Notion MCP 支持的上传和 file 块接口添加附件；若不支持本地上传，交付本地文件链接并说明附件未上传。写完后重新加载页面，确认附件存在。
- 表格单元格里不要在行内代码后面用“ + ”连接（如 `a.c` + `b.c`），Notion 会把它转换成“•”；改用“、”或“和”。
